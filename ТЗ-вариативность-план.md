# План реализации §17 «Вариативность черновиков» (v3, 2026-06-10)

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ суб-скилл — `superpowers:subagent-driven-development`
> (рекомендуется) или `superpowers:executing-plans`. Шаги отмечены чекбоксами `- [ ]`.
> Спека — **§17 в `ТЗ.md` (v3)**; этот план — пошаговая реализация ровно той спеки.

**Цель:** из одного введённого объявления (название + описание + фото) сервис локально
готовит N различающихся вариантов с превью, и пакетный публикатор заливает их как N
разных черновиков.

**Архитектура:** два чистых модуля без сети (`text_variation.py` — комбинаторный перефраз,
`photo_variation.py` — Pillow-пресеты) + оркестратор фазы подготовки (`preparation.py`,
фоновая задача, `PREP_JOBS`), новые эндпоинты `/api/publish/prepare*`, расширение
`run_publish_job` параметром `prep_id`, превью-экран в DraftPage. Никакого Claude API,
никакого `llm.py` (решение §17.1 v3).

**Стек:** Python 3.11, FastAPI, Pillow (единственная новая зависимость), React+Vite.

### Задача 2: `backend/text_variation.py`

Модуль БЕЗ сети и БЕЗ импортов из publisher/app. Публичный интерфейс:

```python
@dataclass(frozen=True)
class TextVariant:
    title: str
    description: str
    notes: str = ""  # например: "вариант 1 — оригинал" / "форс-добавлена шапка (похожесть)"

def vary_listing(
    title: str,
    description: str,
    n: int,
    *,
    seed: int | None = None,
    facts: dict[str, str] | None = None,  # ключи: "size", "condition", "brand" (опц.)
) -> list[TextVariant]: ...
```

Внутреннее устройство (детали — §17.3 ТЗ.md):

```python
# Разбиение на предложения: по [.!?…] с сохранением знака; абзацы (\n\n) — границы,
# через которые предложения не переставляются.
_SENT_RE = re.compile(r"[^.!?…\n]+[.!?…]?")

def _jaccard_3grams(a: str, b: str) -> float:
    """Похожесть описаний: Jaccard по 3-граммам слов (нормализованных, без пунктуации)."""
    def grams(s: str) -> set[tuple[str, ...]]:
        words = re.findall(r"\w+", s.lower())
        return set(zip(words, words[1:], words[2:])) or {tuple(words)}
    ga, gb = grams(a), grams(b)
    return len(ga & gb) / max(1, len(ga | gb))

SIMILARITY_MAX = 0.85   # пары описаний выше порога пересобираются
REBUILD_ATTEMPTS = 5    # потом форс-добавка другой шапки/подвала
```

Словарь синонимов — модульная константа `SYNONYMS: dict[str, list[str]]`, **не менее 50
пар** лексики объявлений; замена только целых слов/фраз (через `\b`-regex), регистр
сохранять по первому символу. Примеры для затравки (довести до ≥50 по этому образцу):

```python
SYNONYMS = {
    "продаю": ["продам", "продаётся"],
    "отличное состояние": ["прекрасное состояние", "идеальное состояние"],
    "хорошее состояние": ["достойное состояние"],
    "торг": ["торг уместен", "возможен торг"],
    "новый": ["абсолютно новый", "совершенно новый"],
    "качественный": ["добротный"],
    "недорого": ["по приятной цене"],
    "быстро отвечу": ["отвечаю быстро"],
    "самовывоз": ["заберёте сами"],
    "отправлю": ["отправка возможна", "вышлю"],
    # ... довести до >=50 пар той же стилистики, ничего не выдумывающих про товар
}
```

Шапки/подвалы — пулы `HEADERS`/`FOOTERS` по ≥10 нейтральных шаблонов (плейсхолдеры
`{brand}`, `{size}` подставлять только если есть в `facts`, иначе шаблон без них):

```python
HEADERS = [
    "", "Отличный вариант на каждый день.", "Смотрите фото — всё как есть.",
    "Вещь в наличии, готова к продаже.", ...
]
FOOTERS = [
    "", "Отвечу на вопросы в сообщениях.", "Самовывоз или отправка — как удобно.",
    "Пишите — договоримся.", ...
]
```

Вариация названия: перестановка слов (бренд/тип) + добавки из `facts`
(«Пиджак Hugo Boss 48 M» / «Hugo Boss пиджак, 48 (M), отличное состояние»); названия
попарно различны как строки; длина ≤ 50 символов (лимит Авито — обрезать по словам).

Гарантии (это и проверяют самотесты):
- `len(result) == n`, все описания/названия непусты;
- `result[0].title == title` и `result[0].description == description` (оригинал);
- все пары описаний: `_jaccard_3grams ≤ SIMILARITY_MAX`; названия попарно различны;
- тот же `seed` → побайтно тот же результат; разные seed → другой;
- никаких новых «фактов»: каждое слово варианта либо из оригинала, либо из
  SYNONYMS/HEADERS/FOOTERS/facts.

### Задача 3: `backend/photo_variation.py`

Интерфейс (детали — §17.3 ТЗ.md; **зеркала в пуле НЕТ** — §17.1):

```python
@dataclass(frozen=True)
class Preset:
    name: str                 # человекочитаемо, по-русски: "зум 4% + теплее"
    zoom_pct: float = 0.0     # 0 или 2..6 — центральный/смещённый кроп
    rotate_deg: float = 0.0   # 0 или ±1..2 — с обрезкой полей (без чёрных углов)
    brightness: float = 1.0   # 0.92..1.08
    contrast: float = 1.0     # 0.92..1.08
    saturation: float = 1.0   # 0.92..1.08
    temp_shift: int = 0       # -8..+8 — сдвиг каналов R/B (теплее/холоднее)
    noise_alpha: float = 0.0  # 0 или 0.01..0.03 — Image.blend с Image.effect_noise
    jpeg_quality: int = 92    # 85..95

def build_presets(n: int, seed: int | None = None) -> list[Preset]: ...
def apply_preset(image_bytes: bytes, preset: Preset) -> bytes: ...
```

Требования реализации:
- пресет №1 — нейтральный (`name="оригинал (только EXIF)"`, все параметры дефолтные):
  только чистка EXIF + пере-сохранение;
- каждый следующий — связная комбинация 2–3 «семейств» с конкретными значениями от seed;
  пресеты попарно различны (как кортежи параметров) при любом n ≤ 10;
- чистка EXIF у ВСЕХ: пересоздание через `Image.new(img.mode, img.size)` + `paste`
  либо сохранение без параметра `exif`;
- шум без numpy: `noise = Image.effect_noise(img.size, 12).convert(img.mode)`,
  затем `Image.blend(img, noise, preset.noise_alpha)`;
- формат выхода = формат входа (JPEG→JPEG c `quality=preset.jpeg_quality`, PNG→PNG
  с `optimize=True`); вход HEIC Pillow не откроет → лог + вернуть оригинал + заметка
  (правило «ошибка фото → оригинал», §17.3); CMYK → `convert("RGB")`;
- любая ошибка `apply_preset` на конкретном фото → лог + оригинал (не исключение наружу).
