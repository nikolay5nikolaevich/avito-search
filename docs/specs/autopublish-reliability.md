# Надёжная автопубликация Авито

## Цель

Устранить подтверждённые в боевых прогонах причины остановки пакета, потери
качества и незаметного превышения бюджета. Повторный запуск после частичного
успеха не должен начинать пакет сначала.

## Согласованная логика

- Перед пакетом открывается отдельная предполётная вкладка Авито. Она проверяет
  сеть, категорию и бренд до загрузки фотографий и до финансовых действий.
- Если введённый бренд отсутствует в подсказках, используется штатное значение
  «Без бренда». Если сама категория не предлагает «Без бренда», пакет
  останавливается до загрузки фото.
- `view_price` остаётся желаемой стоимостью просмотра. Новое поле
  `view_price_max` — жёсткий потолок. Минимум Авито можно принять только когда
  он не превышает потолок. Для старого API без `view_price_max` потолок равен
  `view_price`, поэтому скрытого перерасхода нет.
- Фактическая стоимость и фактически выбранный бренд записываются в состояние
  задачи и показываются в результате.
- Адрес проверяется одинаково на frontend и backend: требуется номер дома и
  признак структурированного адреса (тип улицы или разделение улицы и дома
  запятой). Если Авито всё равно применил только город, публикация продолжается
  согласно прежнему решению пользователя, но предупреждение возвращается в UI.
- Неполный или непроверяемый комплект фото не отправляется дальше к публикации.
- Сетевые ретраи разрешены только для безопасных GET-навигаций. Финансовые
  кнопки остаются at-most-once и не ретраятся после неопределённого результата.
- После каждого полностью отправленного объявления checkpoint атомарно
  сохраняется на диск. Возобновление начинает со следующего подтверждённого
  индекса; незавершённое текущее объявление не считается опубликованным.
- После перезапуска сервера незавершённые publish-задачи и готовые prep-папки
  восстанавливаются из `tmp/publish`.

## Исправления потока

1. Гео-клик выполняется с `no_wait_after=True` внутри `GEO_RETRIES`; ошибка
   клика считается ошибкой попытки, а не отсутствием селектора.
2. Открытие `/additem` ретраит подтверждённые временные сетевые ошибки с
   паузами 5, 15 и 30 секунд. Лишняя навигация между объявлениями удаляется.
3. Hidden-ID известной категории ожидаются до таймаута. Проверка хлебных крошек
   используется только когда у профиля нет точных ID.
4. Рабочий селектор фото ставится первым. Недобор превью после ожидания
   завершает задачу до создания объявления.
5. CDP-диагностика считает только `type=page`; закрывать разрешено только
   доказанно зависшие вкладки Авито и точные остаточные publish-маршруты.

## Checkpoint и resume

В `tmp/publish/<job_id>/publish-state.json` атомарно хранятся данные черновика,
состояние задачи, `prep_id`, опубликованные item ID/URL, фактические цены,
предупреждения адресов и индекс следующего объявления. Endpoint
`POST /api/publish/resume/{job_id}` разрешён только для восстановленной либо
терминально остановленной задачи и только когда фоновой запуск уже не активен.

## Проверка

- Python unit-тесты воспроизводят гео-гонку, каждый сетевой код, потолок цены,
  fallback бренда, адресную валидацию, недобор фото и checkpoint/resume.
- Frontend unit-тесты проверяют новые поля, валидацию и нормализацию результата.
- Smoke-тест API проверяет частичный успех и возобновление без повторной отправки.
- Финально выполняются все Python-тесты, Node-тесты, smoke и `npm run build`.
