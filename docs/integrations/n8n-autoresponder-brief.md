# Автоответчик и квалификатор лидов на Авито (n8n)

Бриф от 26.08.2026. Проект **не начат** — это описание того, что делаем.

## Одной фразой
Сервис отвечает покупателям на Авито вместо продавца и передаёт человеку только
те диалоги, где нужен человек.

## Зачем
Скорость первого ответа на Авито напрямую конвертируется в продажи. Бот отвечает
за секунды в три часа ночи. Плюс закрывает дыру текущего проекта: сейчас он
заливает объявления и не знает, что с ними стало дальше.

## Поток данных
```
Новое сообщение в Авито
  → приём (webhook или polling Messenger API)
  → сбор контекста: какое объявление, что в нём написано, история диалога
  → классификация: типовой вопрос / горячий лид / мусор
  → ответ Claude  ИЛИ  эскалация в Telegram
  → отправка через Messenger API
  → лог в SQLite
```

## Три исхода классификации
| Класс | Примеры | Что делает бот |
|---|---|---|
| Типовой | «актуально?», «какой размер?», «состояние?», «есть ли ещё?» | отвечает сам по карточке объявления |
| Горячий | «беру», «когда встретимся», «отдадите за X?», доставка | черновик ответа + алерт в Telegram, ждёт человека |
| Мусор | спам, услуги продвижения, «куплю всё за 500» | молча в лог |

## Красные линии — всегда человек, без исключений
- Любое обещание цены ниже указанной в объявлении.
- Предоплата, реквизиты, споры по Авито Доставке.
- Адрес, время встречи, номер телефона.
- Всё, чего нет в карточке объявления — бот **не выдумывает** характеристики.
- Сообщение, которое классификатор не отнёс уверенно ни к одному классу.

Тот же принцип, что в `publisher.py`: непонятная ситуация — стоп, не угадываем.

## Данные, которые нужны боту
- Карточка объявления: заголовок, цена, описание, параметры (размер, бренд, состояние).
- История диалога.
- **Минимальная цена**, за которую продавец готов отдать. Её надо задавать при
  подготовке варианта и хранить рядом с объявлением — сейчас такого поля нет.

## Компоненты
- **n8n** — оркестрация, локально в Docker.
- **FastAPI (`app.py`)** — хранит карточки и `min_price`, отдаёт контекст по item_id.
- **Avito Messenger API** — приём и отправка сообщений.
- **Claude API** — классификация и генерация ответа.
- **Telegram** — пульт эскалации с кнопками.
- **SQLite** — лог диалогов и состояний.

Публикация остаётся в Python на CDP и в этот контур не входит.

## Что подготовить до старта
1. `client_id` / `client_secret` в личном кабинете Авито, OAuth2 client_credentials,
   токен живёт ~24 ч — нужен автоматический рефреш.
2. Проверить, что Messenger API вообще доступен на этом аккаунте.
3. Приём событий: webhook требует публичный HTTPS-URL, а n8n локальный.
   Либо туннель (cloudflared / ngrok), либо **polling `getChats` раз в 30–60 сек** —
   для MVP проще и надёжнее.
4. Бот от BotFather + свой `chat_id`.
5. Claude API key.
6. n8n в Docker видит бэкенд как `http://host.docker.internal:7777`, не localhost.

## Этапы — руки снимаем с руля постепенно
- **Э1. Только чтение.** Ловим сообщения, пересылаем в Telegram. Бот не отвечает
  вообще. Неделя работы — копим реальные вопросы покупателей.
- **Э2. Черновики.** Классификатор + предложенный ответ с кнопкой «отправить».
  Без нажатия не уходит ничего.
- **Э3. Автоответ по белому списку.** Сам отвечает только на типовые вопросы,
  подтверждённые статистикой Э1. Остальное — как в Э2.
- **Э4. Расширение белого списка** по накопленным данным.

Сразу включать автоответ нельзя: цена ошибки — репутация аккаунта продавца.

## Риски
- Бот отвечает ерунду от лица живого аккаунта → жалобы, блокировка. Лечится этапностью.
- Массовые мгновенные однотипные ответы выглядят как бот → задержка 20–60 сек,
  живой тон, не повторять формулировки дословно.
- Гео: запросы к `api.avito.ru` и получение токена — с РУ-IP.

## Метрики успеха
Доля диалогов, закрытых без участия человека. Время первого ответа.
Сколько раз бот ошибся и пришлось вмешиваться.

## Открытый вопрос
Доступ к официальному API Авито не подтверждён. Пункт 2 из подготовки — первое,
что нужно проверить: без Messenger API весь проект не существует.
