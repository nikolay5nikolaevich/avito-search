# iPhone 17: фото прямо в папке памяти

Пользователь добавил четыре JPEG в `library/iphone/Iphone 17/256 GB/`.
Модель определялась, но `catalog` обходил только вложенные папки паков,
поэтому возвращал пустой список. Интерфейс показывал общую ошибку порядка
фотографий вместо причины из каталога.

## Результат

`<модель>/<память>/*.jpg` теперь считается паком «Основной» с внутренним
ID `__memory__`. Именованные пакеты в подпапках продолжают работать рядом.
Выбор, JPEG-превью и пользовательская перестановка фото работают через тот же
конвейер. Исходники не переименовывались и не переносились.

Регистр и повторные пробелы в имени папки модели несущественны.
Поддерживаются модели из существующего справочника проекта, новые модели
Авито автоматически не добавляются. Общий эталон описания сохраняется.

В форме смена модели очищает старый preview/order, а ключ модели и памяти
не позволяет перенести случайный пак старой модели из сохранённой формы.
Ошибка каталога сохраняется дословно.

Изменения: `backend/iphone_library.py`, `frontend/src/lib/iphoneLibrary.js`,
`frontend/src/pages/DraftPage.jsx`, `docs/iphone-library.md`, тесты
`tests/test_iphone_direct_memory_pack.py`, `frontend/src/lib/iphoneLibraryPreview.test.mjs`.

## Проверки

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -p 'test_iphone_*.py'
cd frontend
npm test
npm run build
```

66 тестов iPhone прошли, в том числе 7 новых для прямых паков и локальная
браузерная проверка формы. Проверены совместимость именованных паков, лимиты,
разделение памяти и моделей, JPEG-превью и защита путей.
Фронтенд: 72 passed. Сборка успешна, `git diff --check` без ошибок.

После проверки отсутствия незавершённых публикаций сервер перезапущен.
Живой GET `/api/publish/iphone-library` для iPhone 17 / 256 ГБ вернул
`error=""`, доступный «Основной» и четыре фото. Проверка select_materials
с теми же фото и общим текстом прошла, публикация новой формы не запускалась.

## Состояние публикаций

На момент проверки последний пакет `ea01b7da-6966-4462-a874-365d0598ff30`
имел статус `done`, `items_published=5`, `items_total=5`; `/api/publish/pending`
вернул пустой список. Старые задачи повторно не запускались.
