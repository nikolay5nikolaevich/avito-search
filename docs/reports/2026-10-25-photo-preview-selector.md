# 25.10.2026: загруженные фото не распознаны

Задача `20385858-5ba2-4dd3-ac2f-3d42e0d8d85a` остановилась на `upload_photos`
первого объявления из пяти: за 120 секунд сервис насчитал 0 из 6 превью.

## Факты и причина

Локальные источники: `logs/publisher.log`, `debug/publish/<job_id>/`,
`debug/photo_diag_20261025T180928Z/`, checkpoint задачи. Персональные данные
и исходный HTML в отчёт и тесты не переносились.

- Шесть upload-ответов HTTP 200.
- На снимке формы все шесть фото видны.
- В DOM шесть `img` с маркерами `preview(<динамический id>)/image`
  под `data-marker="images"`.
- Все пять прежних кандидатов возвращают 0 на сохранённом HTML.
- Новый точный селектор возвращает 6 на том же HTML.

Причина — устаревшие селекторы превью. Увеличение таймаута, смена фотографий
или повторная загрузка не устраняют этот дефект. Общий счётчик CDN-картинок
страницы также непригоден: он включает изображения вне формы загрузки.

## Изменения

- `backend/avito_publish_selectors.py`: новый первый кандидат
  `[data-marker='images'] img[data-marker^='preview('][data-marker$=')/image']`;
  старые кандидаты оставлены для прежней разметки. Исправлен устаревший
  комментарий о продолжении после фиксированной паузы.
- `tests/test_photo_preview_dom.py`: синтетическая локальная форма из
  подтверждённых маркеров, без копирования пользовательского дампа.
- `tests/test_photo_preview_wait.py`: добавлена общая изоляция от рабочих
  логов, Chrome CDP и каталогов публикации.
- `AGENTS.md`: закреплена просьба пользователя сопровождать публикации и
  сохранять причины и решения в реестре.
- `docs/reports/publish-error-registry.md`: E-20 и уточнения исторических E-08/E-09.

Денежные действия, таймаут и правило полного набора фото не изменялись.

## Проверки

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -p 'test_photo_preview_*.py' -v
```

Результат: 6 passed. До исправления новый DOM-тест воспроизводил ложный `0/6`.
После исправления проверены: ровно шесть превью при вложенных контейнерах;
посторонние картинки; недобор 5/6; смена blob/CDN-источника; повторный опрос,
если фото появились позднее. Локальный Chrome headless, внешняя сеть запрещена.

## Состояние и следующий прогон

Checkpoint прочитан без изменений: `status=failed`, `step=upload_photos`,
`item_index=1`, `items_total=5`, `items_published=0`, `money_click=null`.
Штатный `resume_plan`: `retry_item`, `start_index=1`. Для применения исправления
нужен перезапуск сервера, затем возобновление существующей задачи пользователем.
Реальная повторная публикация в рамках разбора не запускалась; её результат
потребуется проверить по новым логам и checkpoint.
