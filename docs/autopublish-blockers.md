# Что мешает автопубликации работать без ручного вмешательства

Разбор боевого прогона 16.08.2026 (задача `36e15dd6`, кроссовки Heckel, 16 адресов).
Результат прогона: **12 опубликовано, 4 не дошли**. До него — четыре запуска подряд
упали на 0 опубликованных, каждый раз по новой причине.

Документ отвечает на один вопрос: **что нужно починить, чтобы пакет проходил
целиком, без остановок и без участия человека.**

Смежные документы:
- `docs/publish-error-registry.md` — полный реестр ошибок с диагностикой (E-01…E-16).
- `docs/avito-publication-errors-report-2026-08-16.md` — разбор прогона 17/17.

## B-1. Бренда нет в справочнике Авито

**Что произошло.** Задача `cf26f401` встала на шаге 7/16:
```
14:18:00 ERROR Не удалось выбрать бренд «Heckel» в подсказках Авито
```
Отправлено 0 из 17.

**Причина.** Спецобувь Heckel в справочнике брендов Авито отсутствует
(живая разведка: по запросу `Heckel` — 0 подсказок). Автокомплит Авито
фиксирует значение **только кликом по пункту списка**; набранный текст
без выбора не принимается, и форма не уходит дальше.

**Почему стоп был правильным.** Код не имел права подставить похожий бренд:
чужая марка в карточке — искажение товара.

**Решение (внедрено 16.08.2026).** У Авито есть штатный пункт «Без бренда» —
форма сама подсказывает «Выберите "Без бренда", если марка не указана».
Пустой бренд теперь маппится на него:
```python
# publisher.py
NO_BRAND_LABEL: str = "Без бренда"
brand_text = _brand_text_for_avito(brand) or NO_BRAND_LABEL
```
Плюс `brand` убран из обязательных полей `validate_publish_form`.

**Что осталось сделать для полной автономности.**
1. Проверять бренд **до старта пакета**, а не на первом объявлении: один
   заход на форму, проверка наличия в подсказках, и сразу понятно — брать
   марку или «Без бренда». Сейчас ошибка вскрывается после загрузки фото.
2. Пункт «Без бренда» есть не во всех категориях — при внедрении новой
   категории проверять его наличие разведкой.

## B-2. Заданная цена просмотра ниже минимума Авито

**Что произошло.** Задача `496fe201` встала на шаге 12/16:
```
14:55:56 needs_user_action Для объявления №1 минимальная стоимость просмотра — 1.7 ₽
```
Пользователь задал 0,4 ₽ — Авито требует минимум 1,7 ₽. Отправлено 0 из 16.

**Причина.** Минимальная стоимость просмотра **зависит от города и категории**
и заранее неизвестна. Форма сервиса позволяет ввести любое число, а реальный
минимум выясняется только на экране `/cpxpromo/<id>`, то есть после того,
как объявление уже создано.

**Почему стоп был правильным.** Это платный параметр: подставлять другое
значение молча нельзя.

**Решение (внедрено 16.08.2026, по решению пользователя «всегда бери минимум»).**
Slider на этом шаге уже уведён в минимальную позицию (`Home`), поэтому принять
минимум безопасно — лишних движений нет, берётся ровно то, что показывает Авито:
```python
if current > view_price:
    logger.warning("Объявление №%d: заданная %s ₽ ниже минимума %s ₽ — публикуем по минимуму", ...)
    return current_text
```
Обратная сверка ослаблена ровно на этот случай: `actual > view_price` больше
не ошибка, любое иное расхождение — по-прежнему стоп.
Покрыто тестами `test_price_below_avito_minimum_takes_minimum`
и `test_price_above_avito_minimum_is_still_exact`.

**Факт прогона.** Все 12 объявлений опубликованы по 1,7 ₽ вместо заданных 0,4 ₽ —
**в 4,25 раза дороже плана** (27,20 ₽ вместо 6,40 ₽ за 16 объявлений).

**Что осталось сделать.**
1. **Потолок цены.** Сейчас берётся любой минимум, каким бы он ни был. Нужен
   параметр «не дороже X ₽ за просмотр»: выше потолка — стоп. Без него
   дорогой город молча съест бюджет.
2. **Показывать факт в интерфейсе.** Пользователь задал 0,4 ₽, а списывается
   1,7 ₽ — сейчас это видно только в логе.
3. **Узнавать минимум заранее** — например, по первому объявлению — и показывать
   реальную смету до старта пакета.

## B-3. Адрес в неузнаваемом формате

**Что произошло.** Адрес №1 был записан как `королева 26` — без слова «улица»,
с маленькой буквы. Авито не распознал и подставил **голый город**:
```
Адрес, попытка 1/3: 'Санкт-Петербург, королева 26'
Гео: выбран адрес 'Санкт-Петербург'      ← улица потерялась
```
В боевом прогоне так же ушло объявление №2 (Мурманск).

**Причина.** Контроль применения адреса проверял только, что hidden-поля
`address` и `locationId` **непустые**. Голый город это условие проходит.

**Следствие.** Объявление публикуется без улицы — молча, без следа в интерфейсе.

**Решение (внедрено 16.08.2026, по решению пользователя «оставь просто город»).**
Поведение сохранено — публикуем как есть, — но случай теперь виден в логе:
```
Адрес без улицы: запрошено 'Мурманск, улица Чумбарова-Лучинского, 19',
Авито применил только город 'Мурманск' — объявление публикуется без улицы
```

**Что осталось сделать.**
1. **Валидация формата адреса на фронте**, до старта: «улица Королёва, 26»
   вместо «королева 26». Дешевле всего — здесь и лечится.
2. **Отдавать список «без улицы» в результат задачи**, а не только в лог,
   чтобы после пакета было видно, какие карточки неполные.

## B-4. Гонка гео-поля с навигацией страницы

**Что произошло.** Пакет остановился на 13-м объявлении из 16:
```
15:54:47 SELECTOR_MISS: гео-поле [data-marker='geo/search-input']:
         Locator.click: Timeout 10000ms exceeded
  - locator resolved to <input ... data-marker="geo/search-input" ...>
  - performing click action
  - click action done
  - waiting for scheduled navigations to finish     ← завис здесь
```

**Причина.** Поле **нашлось**, клик **прошёл** — и Playwright завис, ожидая
завершения навигации, которую страница затеяла в этот момент. Это гонка,
а не отсутствие селектора. Сообщение «Гео-поле не найдено» вводит в заблуждение:
поле было на месте.

**Следствие.** 4 объявления (Краснознаменск, Люберцы, Мытищи, Подольск)
остались неопубликованными; пакет пришлось добивать отдельно.

**Решение (не внедрено).**
1. Клик с `no_wait_after=True` — не ждать навигацию там, где её не должно быть:
   ```python
   await geo_input.click(timeout=WAIT_SELECTOR_TIMEOUT_MS, no_wait_after=True)
   ```
2. Обернуть шаг в ретрай: `GEO_RETRIES = 3` уже есть, но исключение на
   `click` выбрасывается наружу **до** цикла ретраев — починить порядок,
   чтобы гонка ретраилась, а не роняла пакет.
3. Исправить текст ошибки: «не удалось кликнуть по гео-полю (возможна гонка
   с навигацией)» вместо «не найдено».

Приоритет высокий: это единственная причина, по которой прогон не дошёл до конца.

## B-5. Временный сетевой сбой при открытии формы

**Что произошло.** Задача `2562fdb7`, шаг 2/16, отправлено 0 из 17:
```
13:55:49 open_form — старт
13:56:12 WARNING DNS Авито временно недоступен  ← 23 с ждали резолва
13:56:18 ERROR   net::ERR_ABORTED
```

**Причина.** Кратковременный сбой в сетевом канале Chrome (DNS не ответил
23 секунды). К моменту разбора Авито работал штатно — сбой прошёл сам.

**Дефект кода.** `_goto_additem_with_dns_retry` ретраит **только**
`ERR_NAME_NOT_RESOLVED`:
```python
is_dns_failure = "net::ERR_NAME_NOT_RESOLVED" in str(exc)
```
`ERR_ABORTED`, `ERR_CONNECTION_RESET`, `ERR_TIMED_OUT` падают сразу.
Задержки `(2.0, 5.0)` с — слишком коротко: вторая попытка ушла через 2 секунды,
когда канал ещё не восстановился.

**Решение (не внедрено).**
1. Ретраить весь класс временных сетевых ошибок, а не одну.
2. Задержки `(5.0, 15.0, 30.0)` — пережить моргание канала.
3. Предполётная проверка достижимости `avito.ru` **перед стартом пакета**:
   один заход, и при неуспехе внятное сообщение вместо падения на первом
   объявлении.

> **Как НЕ диагностировать.** `curl https://www.avito.ru/` из окружения
> ассистента ничего не говорит о доступности Авито для Chrome пользователя:
> каналы разные. Живой Авито отдаёт голому curl **HTTP 403**, а `HTTP 000` —
> это лишь «не прошёл curl». Достоверный признак один: открываются ли
> вкладки Авито в браузере руками.

## B-6. CDP виснет при многих вкладках

**Что произошло.** После нескольких упавших прогонов накопилось 22 CDP-цели
(4 вкладки `/additem` с тяжёлыми формами). `connect_over_cdp` перестал
подключаться вообще:
```
BrowserType.connect_over_cdp: Timeout 90000ms exceeded
  - <ws connected> ws://127.0.0.1:9222/devtools/browser/...
```
Публикация не стартовала, пока пользователь не закрыл вкладки вручную.
После чистки (6 целей) подключение стало мгновенным.

**Причина.** Каждая упавшая задача оставляет открытую вкладку с формой.
Playwright при подключении обходит все цели, тяжёлые формы его вешают.

**Решение (не внедрено).**
1. **Закрывать свою вкладку при любом исходе**, включая падение
   (сейчас при некоторых сбоях страница остаётся).
2. Фильтровать цели при подключении: только `type == "page"` с хостом
   `avito.ru`, игнорируя `iframe`, `worker`, `blob:`.
3. Диагностика вместо немого таймаута: «вижу N целей, ожидаю 1–3».

> **Как считать вкладки.** Только цели `type == "page"`. `grep -c '"type"'`
> считает ещё `iframe` (реклама внутри страниц) и `worker` — при трёх реальных
> вкладках даёт «11» и приводит к ложному выводу «браузер замусорен».

## B-7. Нет checkpoint'а и возобновления

**Что произошло.** После остановки на 13-м из 16 сервис не умеет продолжить
с 13-го. Повторный запуск начал бы с первого и создал 12 дублей —
то есть **двойную оплату**.

**Причина.** Прогресс задачи живёт только в памяти процесса. На диск пишутся
фото, но не состояние: ни список отправленных item ID, ни индекс.

**Следствие.** Каждое падение требует ручной работы: посмотреть
`items_published`, выписать URL'ы, собрать запуск на остаток.
Плюс `prep_id` теряется при перезапуске сервера, хотя папка вариантов цела.

**Решение (не внедрено).**
1. Писать item ID в файл задачи **сразу после каждого** `skip_services`.
2. Режим «продолжить задачу» в API: `POST /api/publish/resume/{job_id}`.
3. Восстанавливать `PREP_JOBS` с диска при старте сервера — папки
   `tmp/publish/prep_*` переживают перезапуск, запись в памяти нет.

Это главный структурный долг: без него ни один сбой не отрабатывается
автоматически.

## Не блокеры, но портят результат

### N-1. Порядок селекторов превью фото

За прогон — **36 промахов** `SELECTOR_MISS`. Рабочий селектор
`[class*='uploader'] img` стоит **четвёртым** в
`PHOTO_PREVIEW_CANDIDATES`, а три первых не находятся никогда:
```python
PHOTO_PREVIEW_CANDIDATES = [
    "[data-marker='image']",        # промах, 5 с
    "[data-marker='thumbnail']",    # промах, 5 с
    "[class*='photo-list'] img",    # промах, 5 с
    "[class*='uploader'] img",      # ← рабочий
]
```
Цена: 15 с на объявление, **4 минуты на пакет из 16**.
Починка — переставить рабочий первым.

### N-2. `fill_description` — 82 секунды на объявление

Самый долгий шаг, среднее 81,8 с, максимум 105 с (при том, что все
остальные шаги вместе — около 25 с). Описание вводится посимвольно
с клавиатуры. На пакет из 16 — **22 минуты из ~35**.

Ускорять осторожно: посимвольный ввод выбран как антибот-мера,
а `.fill()` не работает с contenteditable-редактором Авито.
Разумный шаг — уменьшить задержку между символами и замерить,
не растёт ли доля капчи.

### N-3. Дампы пустые именно там, где нужны

При падениях страница умирает раньше, чем снимается скриншот:
```
Скриншот шага fill_address не снят: Target page, context or browser has been closed
```
В `debug/publish/<job_id>/` остаётся только `error.txt`. Дамп бесполезен
ровно в тех случаях, когда важнее всего.
Починка — снимать скриншот **до** закрытия вкладки (`publisher.py:611`
уже проверяет `_page_is_closed`, но проверка срабатывает слишком поздно).

## План: что чинить, чтобы пакет шёл сам

| Порядок | Что | Закрывает | Эффект |
|---|---|---|---|
| 1 | Гео-клик `no_wait_after` + ретрай гонки | B-4 | единственная причина недохода прогона |
| 2 | Checkpoint + `resume` + восстановление `prep_id` | B-7 | любое падение доигрывается само |
| 3 | Потолок цены просмотра | B-2 | защита бюджета от дорогих городов |
| 4 | Предполётные проверки (сеть, бренд, адреса) | B-1, B-3, B-5 | ошибки данных всплывают до старта, а не на 1-м объявлении |
| 5 | Закрывать вкладку при любом исходе + фильтр целей | B-6 | CDP не залипает между прогонами |
| 6 | Порядок селекторов превью | N-1 | −4 мин на пакет |
| 7 | Скриншот до закрытия страницы | N-3 | дампы становятся полезными |

**Смысл первых четырёх пунктов:** сейчас пакет останавливается на первом же
неожиданном значении и ждёт человека. После них он либо проходит целиком,
либо останавливается **до** траты денег, с понятной причиной.
