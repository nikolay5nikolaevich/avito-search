# Библиотека iPhone

Фото и тексты хранятся на этом компьютере в папке `library/iphone/` внутри
проекта. Сервис читает их локально; в GitHub они не отправляются.

## Как разложить материалы

Создайте общую папку `description` с одним эталонным `.txt` для всех моделей.
Фото разложите по точному названию модели, памяти и паку:

Можно класть фото прямо в папку памяти, без дополнительной папки пака:
`library/iphone/iPhone 17/256 GB/01.jpg`. Такие фото показываются как пак
«Основной». Этот способ можно использовать для следующих поддерживаемых
моделей. Папки с именованными паками по-прежнему работают, в том числе рядом
с отдельными фото в папке памяти. Регистр букв в названии модели не важен:
`Iphone 17` и `iPhone 17` обозначают одну модель.

```text
library/iphone/
  description/
    iphone.txt
  iPhone 17 Pro Max/
    512 GB/
      Стол/
        01.jpg
        02.jpg
      Витрина/
        01.jpg
        02.jpg
    1024 GB/
      Стол/
        01.jpg
        02.jpg
  iPhone 17 Pro/
    256 GB/
      Основной/
        01.jpg
        02.jpg
```

Названия паков произвольные. Память в имени папки — `128 GB`, `256 GB`, `512 GB`,
`1024 GB` (1 ТБ) или `2048 GB` (2 ТБ); набор зависит от модели. Цвет папкой
не задаётся: фотографии разных цветов могут находиться в одном паке.

В одном паке от 1 до 10 фотографий, каждая до 25 МБ. Используйте JPEG или PNG;
GIF и HEIC/HEIF поддерживаются по правилам существующего обработчика
(HEIC/HEIF требуют установленного pillow-heif). Исходный порядок — по имени файла:
называйте их `01.jpg`, `02.jpg` и так далее. Первое фото будет главным.
Пустые, повреждённые и слишком большие паки показаны как недоступные.

Сейчас справочник проекта содержит iPhone 17, 17 Pro, 17 Pro Max, 17e,
18 Pro и 18 Pro Max. Это список поддерживаемых формой проекта моделей.
Обычный iPhone 18 не поддерживается: сервис попросит исправить название.

## Описания

Сохраните один эталонный текст в `library/iphone/description/iphone.txt`
с кодировкой UTF-8, например в Блокноте. Он используется для всех моделей
и объёмов памяти. В общей папке должен лежать ровно один `.txt`.
Можно использовать подстановки:

| В тексте | Что вставится |
| --- | --- |
| `{модель}` | iPhone 17 Pro Max |
| `{память}` | Выбранная память, например 512 ГБ |
| `{цвет}` | Один выбранный цвет |
| `{SIM}` | Выбранный вариант SIM |

Пример структуры (условия продажи впишите свои):

```text
{модель}, {память}. {SIM}.
Новый, не использовался. Неактивированный, коробка запечатана.

Доступные цвета: перечислите свои цвета обычным текстом.
Комплект и условия: ваш текст.
```

Статический список цветов сохраняется как написан. Если в тексте нужен только
один выбранный цвет, используйте `{цвет}`. Дополнительные маркеры вроде `{цена}`
не поддерживаются. Тексты не перефразируются; добавляется уникальный артикул.
Явные противоречия выбранному SIM или состоянию телефона требуют исправления.

В эталоне из пользовательского текста меняются модель, память и строка SIM.
Адрес магазина остаётся обычным текстом: замените `@@@@` на нужные значения
в самом файле. Город из формы не подставляется вместо адреса магазина.
Строка с аппаратным кодом `А3257` исключена, чтобы не попадать в другие модели.

Для совместимости: если общей папки `description` нет, читаются прежние
`<модель>/descriptions/*.txt`. Пустая или неверно заполненная общая папка
блокирует подготовку, без подмены старым текстом.

## Подготовка

1. Выберите категорию iPhone и введите английское название, например
   `iPhone 17 Pro Max` или `17 Pro Max iPhone`.
2. Выберите память, цвет и **SIM**. У SIM нет автоматического значения:
   доступны eSIM, SIM + eSIM, SIM + SIM.
3. Введите цену, потолок просмотра, количество и геолокации, как раньше.
4. Оставьте фотопак «Случайный» или выберите его по названию. Случайный пак
   выбирается сразу и показывается в основной форме. При необходимости нажмите
   «Выбрать случайный заново». После изменения папок нажмите «Обновить библиотеку».
5. Проверьте фотографии под выбором пака. Нажатие на фото открывает его крупнее.
   Меняйте порядок стрелками или перетаскиванием: первое фото будет главным.
   Этот пак и порядок используются во всех карточках. Исходные файлы не меняются.
6. Подготовьте черновики и проверьте фото, тексты и характеристики. Публикация
   запускается отдельной кнопкой.

Во всём запуске используется один фотопак. Все фотографии в каждом объявлении
проходят прежнюю уникализацию. Общий эталонный текст подставляется в каждую
карточку, с отдельным артикулом. Приложить фото вручную в форме iPhone нельзя.

Материалы копируются в подготовку. Последующая правка библиотеки не изменяет
уже подготовленные черновики. Перегенерация карточки сохраняет её пак и исходный
шаблон, обновляя уникализацию. Чтобы использовать другой пак, вернитесь к форме
и подготовьте новые варианты. Незавершённый опубликованный пакет продолжают
штатной кнопкой возобновления, а не повторной подготовкой и публикацией с нуля.

## Запуск после обновления

Остановите прежний сервер сочетанием Ctrl+C в его окне и запустите из корня:

```powershell
python backend/app.py
```

Если интерфейс ещё не собран:

```powershell
cd frontend
npm run build
cd ..
```

База адресов в эту версию не входит. Адреса, контактный телефон и вид объявления
используют существующий сценарий сервиса.
