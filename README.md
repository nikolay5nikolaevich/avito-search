# AI-инструменты для бизнеса на Авито

**Экономия около 120 000 ₽ в год** на ручной выкладке, разборе рынка и
переписке с продавцами. Полный цикл работы продавца на Авито — от «что и где
продавать» до публикации десятков объявлений — в одном локальном сервисе.

Первый боевой прогон автовыкладки: **17 из 17 объявлений отправлены**.

---

## Что реализовано

| Модуль | Что делает |
| --- | --- |
| **Автовыкладка** | Одна форма → N уникальных объявлений (текст + фото) → публикация на Авито подряд, включая экраны цены просмотра и платных услуг. Сбой посреди пакета — продолжение с того же места без повторной оплаты. |
| **Аналитика спроса** | Выдача по 10 городам: средние просмотры в день, топ-3 объявления, выгрузка в CSV, кэш на 24 часа. |
| **Разбор продавца** | Первые N объявлений любого профиля с просмотрами за всё время и за сегодня. |
| **Поиск под перепродажу** | Лоты ниже рынка по модели товара; тексты объявлений разбирает ИИ. |
| **Рассылка** | Сбор продавцов из выдачи и сообщения им в чат Авито. |
| **Рассылка IT** | Сайты компаний из открытых данных и их опубликованные рабочие email. |
| **Агенты** | Сборщик статистики своих объявлений через API Авито и Стратег, который строит гипотезы по цифрам. |

Публикация реальная и платная, поэтому денежный участок работает по принципу
**fail-closed**: незнакомая кнопка, услуга или цена — остановка, а не догадка;
денежный клик никогда не повторяется. Авито банит автоматические браузеры —
сервис работает через обычный Chrome пользователя по CDP.

## AI-assisted development

Весь код проекта написан ИИ-агентами — Claude Code и Codex. Моя часть —
постановка задач, архитектурные решения, приёмка и боевые прогоны на живом Авито.

### Оркестратор и субагенты

Главная сессия Claude Code работает **оркестратором**: декомпозирует задачу,
пишет брифы, принимает результат — и сама код почти не пишет. Исполняют
**субагенты**, каждый под свой класс задач и со своей моделью:

| Субагент | Модель | Задачи |
| --- | --- | --- |
| `executor` | Sonnet | правки по готовому брифу, формы, тесты, конфиги |
| `deep-thinker` | Fable / Opus | дебаг CDP и Playwright, гонки, аудит денежного кода |
| `codex-executor` | Codex (GPT) | исполнение брифа другой моделью |
| `codex-critic` | Codex (GPT) | cross-model review готового диффа |

Независимые задачи идут параллельно, зависимые — последовательно.

### Pipeline задачи

**spec → design → plan → brief → execution → report → acceptance**

Каждая крупная фича проходит эту цепочку целиком, а большие режутся на части
с отдельной приёмкой: автопубликация, например, собрана в три этапа — контракты
и UI, безопасный денежный сценарий, возобновление после сбоя.

### Context engineering

- **[AGENTS.md](AGENTS.md)** — единая инструкция для любого агента: проект,
  правила денежного участка, грабли, рабочий процесс. Codex читает её напрямую.
- **[CLAUDE.md](CLAUDE.md)** — импортирует AGENTS.md и добавляет только
  специфичное для Claude Code: оркестрацию, субагентов, скиллы.
- Оба файла написаны по гайдам Anthropic и OpenAI для сильных моделей: правило
  вместе с причиной, позитивные формулировки, цель через критерий готовности.
- **Persistent memory** — агент копит знания о проекте между сессиями.
- **Permission deny-list** — агенту запрещено читать `.env` с ключами API.

### Инженерные практики

- **Fail-closed на денежном участке.** Незнакомая кнопка, услуга или цена —
  остановка, а не догадка; денежный клик никогда не повторяется.
- **Независимые acceptance-тесты.** Тесты-доказательства пишет агент, который не
  писал код, — заранее и от ожидаемого результата. Сначала red, потом green.
- **Feasibility gate.** Рискованная идея сначала проходит дешёвую проверку с
  порогом. Не прошла — честный `BLOCKED`, а не выдуманный результат.
- **Факты вместо догадок.** Скрипт разведки снимает живые страницы, агент
  разбирает снимки. Каждый боевой прогон получает письменный разбор в
  [docs/reports/](docs/reports/), каждый сбой — запись в реестре ошибок.
- **Аудит перед деньгами.** Изменения денежного участка проходят аудит, где каждую
  находку пытаются опровергнуть. Аудит возобновления публикации — 51 находка.

### Безопасность и секреты

- **Ключи только в `.env`.** `AVITO_CLIENT_ID` и `AVITO_CLIENT_SECRET` лежат в
  `.env` в корне, шаблон — [.env.example](.env.example). Файл исключён из git и
  ни разу не попадал в историю коммитов — проверено перед публикацией.
- **Без лишних зависимостей.** `.env` читает собственный модуль
  `backend/env_file.py` с тестами. В лог пишутся только имена загруженных ключей,
  значения — никогда. Переменные окружения важнее файла.
- **ИИ не видит секретов.** Для Claude Code настроен permission deny-list: чтение
  и запись `.env*` запрещены на уровне инструментов (Read/Edit/Write и `cat`,
  `type`, `Get-Content` в терминале), а не просьбой в промпте. Правило
  продублировано в AGENTS.md для остальных агентов.
- **Сессия Авито не покидает машину.** Сервис не хранит логин и пароль: он
  подключается к Chrome, в котором пользователь вошёл сам. Профиль браузера,
  дампы страниц с персональными данными (`debug/`), логи и базы — вне git.
- **Деньги — fail-closed.** Платные шаги публикации останавливаются при любой
  неопределённости, денежный клик не повторяется.

варианту, — в [docs/ai-workflow.md](docs/ai-workflow.md).

## Быстрый старт

Windows, PowerShell. Нужен Python 3.11+ и Node.js.

**1. Скачать проект**

```powershell
git clone https://github.com/nikolay5nikolaevich/avito-search.git
cd avito-search
```

**2. Поставить зависимости Python**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если PowerShell ругается на политику выполнения — один раз выполни
`Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`
и повтори активацию.

**3. Собрать интерфейс**

```powershell
cd frontend
npm install
npm run build
cd ..
```

**4. Запустить Chrome, в который будет ходить сервис**

```powershell
.\start-chrome.bat
```

Откроется обычный Chrome. Зайди в нём на avito.ru под своим аккаунтом и
**оставь одну вкладку** — лишние вкладки подвешивают подключение.

**5. Запустить сервис**

```powershell
python backend/app.py
```

Открой `http://localhost:7777`.

### Рассылка IT

После запуска сервиса открой `http://localhost:7777/it-outreach`, укажи число
сайтов (от 1 до 100) и нажми «Найти компании». Источник — бесплатные открытые
данные OpenStreetMap, поэтому список неполный; сайты, которые отрисовывают
контакты только JavaScript, могут не дать email. Сервис лишь собирает уже
опубликованные адреса: писем, Gmail и отправки сообщений в этом разделе нет.

### Почему именно живой Chrome

Авито банит любой браузер, запущенный Playwright'ом. Поэтому сервис не поднимает
свой браузер, а подключается по протоколу CDP к настоящему Chrome, который ты
открыл руками и где уже залогинен.

### Переменные окружения

Кладутся в `.env` в корне проекта — образец в `.env.example`.

| Переменная | Зачем |
| --- | --- |
| `AVITO_CDP_URL` | Адрес отладочного порта Chrome. При проблемах с IPv6 — `http://127.0.0.1:9222`. |
| `AVITO_MAX_ITEMS` | Сколько объявлений разбирать на город в аналитике (по умолчанию 150). |
| `AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET` | Ключи API Авито для Сборщика статистики. |

## Структура проекта

```
backend/     сервер и вся логика
frontend/    интерфейс на React, собирается в dist/ и раздаётся сервером
tests/       smoke-прогоны и точечные проверки рискованных мест
docs/        разборы прогонов, спеки, брифы интеграций
debug/       скрипты разведки живых страниц Авито и снятые дампы
n8n/         готовые воркфлоу автоответчика
```

### Backend

| Файл | Что внутри |
| --- | --- |
| `app.py` | Сервер FastAPI: все HTTP-эндпоинты и раздача собранного интерфейса. |
| `publisher.py` | Весь живой сценарий публикации: форма, подсказки, фото, цена, отказ от услуг. |
| `preparation.py` | Готовит N вариантов объявления из одной формы. |
| `text_variation.py`, `photo_variation.py` | Уникализация текста и фото. Без ИИ: текст дословный, различает артикул; фото — небольшой зум. |
| `category_profiles.py` | Профили категорий: какие поля и размерные сетки у пиджаков, кроссовок, жилетов и футболок. |
| `avito_publish_selectors.py` | Селекторы формы публикации. |
| `avito_selectors.py` | Селекторы страницы выдачи. Не путать с предыдущим. |
| `parser.py`, `analytics.py`, `cities.py`, `filters.py`, `cache.py` | Аналитика спроса: сбор, подсчёт метрик, справочник городов, кэш. |
| `outreach.py`, `outreach_store.py` | Рассылка продавцам и её история. |
| `agents_registry.py`, `journal.py`, `stats_collector.py`, `strategist.py` | Реестр агентов, общий журнал событий, сбор статистики и генерация гипотез. |
| `browser.py` | Подключение к Chrome по CDP. |
| `diag.py` | Диагностика: снимает страницу и складывает артефакты в `debug/`. |
| `publish_state.py`, `address_generator.py`, `env_file.py` | Состояние задачи публикации, генерация адресов, чтение `.env`. |

### Frontend

| Файл | Что внутри |
| --- | --- |

| `src/pages/DraftPage.jsx` | Форма объявления, предпросмотр вариантов и запуск публикации. |
| `src/pages/OutreachPage.jsx` | Сбор продавцов и отправка сообщений. |
