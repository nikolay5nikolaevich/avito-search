# ТЗ: фикс ложного провала шага `save_draft` (пакет обрывается на 1-м черновике)

> Дата: 2026-06-10. Точечный фикс поверх основного `ТЗ.md` (v2).
> Причина появления: первый живой прогон пакета (job `918667fb-5229-4c82-a88d-edb6a484e4d7`,
> `drafts_count=3`) показал баг детекции успеха сохранения. Корень РАЗОБРАН и ДОКАЗАН
> (см. §3) — это ТЗ описывает только реализацию фикса, повторное расследование не нужно.

## 1. Минимальный контекст для входа

Проект — локальный сервис вокруг Авито (аналитика спроса + черновики объявлений).
Общие правила — `CLAUDE.md`, полное ТЗ эпика черновиков — `ТЗ.md`. Ключевое для фикса:

- `backend/publisher.py` — стейт-машина 12 шагов сохранения черновика
  (`connect_chrome → open_form → select_category → … → fill_address → save_draft → done`),
  пакетный режим N черновиков (`run_publish_job`, ТЗ.md §16). **Весь фикс — в этом файле.**
- `backend/app.py` — `PUBLISH_JOBS`, эндпоинты `/api/publish/start|status|result`. Не трогать
  (кроме случая, если изменится сигнатура `_dump_failure` — см. Задачу 3, вызов в publisher.py).
- `backend/avito_publish_selectors.py` — селекторы формы публикации + самотест-страж.
- Тесты: `tests/publish_smoke_test.py` (веб-слой на синтетике, 20 проверок),
  `tests/smoke_test.py` (аналитика, регрессия), самотесты в `__main__` модулей.
- Браузер — живой Chrome пользователя через CDP (`start-chrome.bat`, порт 9222);
  публикатор работает в СВОЕЙ вкладке (`context.new_page()`).

## 2. ЖЁСТКИЕ ПРАВИЛА БЕЗОПАСНОСТИ (нарушение = провал задачи)

1. **НЕ кликать кнопку «Продолжить»** (`[data-marker='item-edit/button-next']`) — это

   `avito_publish_selectors.py` это проверяет — не ослаблять.
2. **НЕ запускать публикатор против живого Авито.** Вся проверка кода — синтетические
   тесты (§7). Живой прогон делает ТОЛЬКО пользователь руками (§8).
3. Не трогать аналитику (`parser.py`, `analytics.py` и т.д.) и браузер пользователя
   (закрывать только свои вкладки).
4. Стиль: PEP 8, type hints, комментарии и логи по-русски, `logging` не `print`,
   ошибка шага → статус задачи, не падение процесса.

## 3. Симптом и доказанный корень (расследовано 2026-06-10)

**Симптом.** Пакет `drafts_count=3`: все шаги до «Адрес» зелёные, шаг «Сохранение
черновика» красный: «После „Сохранить и выйти“ не произошла навигация со страницы формы:
Timeout 29250ms exceeded. … Сохранено 0 из 3». Папка дампа `debug/publish/{job_id}/`
ПУСТАЯ, хотя UI пишет «Дамп сохранён … проверьте скриншот». **При этом черновик №1 реально
сохранён** — пользователь видел его в аккаунте (Мои объявления → Черновики), браузер после
клика ушёл на «Мои объявления».

**Улики из `logs/publisher.log`:**

```
09:15:46  INFO   Клик «Сохранить и выйти», ждём навигацию со страницы формы…
09:16:16  ERROR  …шаг save_draft: failed — …не произошла навигация…: Timeout 29250ms exceeded.
                 ============ logs ============ "domcontentloaded" event fired ============
09:16:16  WARNING Скриншот шага save_draft не снят: Page.screenshot: Target page, context or browser has been closed
09:16:16  WARNING HTML шага save_draft не сохранён: Page.content: Target page, context or browser has been closed
09:16:16  INFO   Дамп шага save_draft сохранён в debug\publish\918667fb-…   ← ЛОЖЬ: папка пуста
```

**Корень.** После «Сохранить и выйти» Авито уводит на «Мои объявления» так, что вкладка
публикатора закрывается/подменяется (target swap: prerender-активация либо открытие в новой
вкладке) — старый объект `page` Playwright становится мёртвым. Текущая детекция успеха в
`_step_save_draft` (publisher.py:1088) — единственная: `page.wait_for_url(λ: url ушёл с
/additem)` на этом мёртвом объекте → честно отвисает 30 с → `StepError` → `run_publish_job`
прерывает пакетный цикл → `drafts_saved=0`, черновики 2–3 не делаются.

**Важно:** логика «после сохранения снова идти на /additem за следующим черновиком» УЖЕ
реализована — цикл `run_publish_job` (publisher.py:1248–1263) на каждой итерации вызывает
`_run_single_draft` → `_step_open_form` → `goto /additem`. Её НЕ менять — она просто не
достигается из-за ложного провала. Чинится детекция успеха, а не навигация.

## 4. Задача 1 — новый критерий успеха `save_draft` (ядро фикса)

Файл `backend/publisher.py`, функция `_step_save_draft` (~строка 1053). Поиск кнопки и клик
оставить как есть. Заменить блок `page.wait_for_url(...)` на вызов нового хелпера, например
`_wait_form_exited(page, url_before) -> tuple[str, str]` (исход, итоговый URL):

- Опрос каждые ~0.5 с, суммарно до новой константы `SAVE_EXIT_TIMEOUT_S: float = 30.0`
  (рядом с остальными константами, ~строка 74). Каждый тик обёрнут в try/except — страница
  может умереть между проверками (умерла во время probe → исход `page_closed`).
- УСПЕХ — любой из исходов (проверять в этом порядке):
  1. `page.is_closed()` → исход `page_closed`. Обоснование, почему закрытие вкладки =
     успех: кликнута единственная безопасная кнопка, Авито автосохраняет форму по мере
     заполнения (ТЗ.md §5), закрытие формы после клика = выход с сохранением.
  2. `page.url` изменился относительно `url_before` И не содержит `additem` → `navigated`.
  3. Кнопка «Сохранить и выйти» больше НЕ видна и хлебные крошки категории
     (`psel.CATEGORY_TITLE`) НЕ видны (через существующий `_selector_now_visible`) →
     исход `form_gone` (форма закрылась без смены URL).
- Итоговый URL: при `navigated` — фактический `page.url`; при `page_closed`/`form_gone` —
  последний известный URL (запоминать на каждом тике); если он всё ещё `/additem` —
  вернуть пустую строку. ПРОВЕРИТЬ, что `saved_urls` с пустой строкой не ломает
  `/api/publish/result` и рендер в `frontend/src/pages/DraftPage.jsx` (если ломает —
  подставлять понятную заглушку вида «(вкладка закрыта Авито — URL неизвестен)»).
- Логи: на тике — `logger.debug` (url, is_closed); итог — `logger.info` с исходом;
  если за 30 с ни один исход не наступил — `logger.warning` со списком URL всех вкладок
  `page.context.pages` (диагностика на случай нового механизма Авито) и `StepError`
  с прежним по смыслу текстом ошибки.
- `WAIT_FORM_TIMEOUT_MS` в других шагах не трогать.

## 5. Задача 2 — живучесть пакетного цикла

Файл `backend/publisher.py`, цикл по черновикам в `run_publish_job` (~строка 1248).
В начале каждой итерации: если `page is None or page.is_closed()` → открыть новую вкладку
`page = await context.new_page()` (`context` уже в области видимости) + `logger.info`
(«вкладка пересоздана после закрытия Авито»). Старую вкладку не трогать — она уже закрыта.
Больше в цикле НИЧЕГО не менять: защита от переоткрытого черновика
(`_guard_against_reopened_draft`) и паузы 5–15 с уже на месте. Блок `finally`
(закрытие своей вкладки) должен переживать мёртвую `page` — он уже в try/except, проверить.

## 6. Задача 3 — честный `_dump_failure`

Файл `backend/publisher.py`, `_dump_failure` (~строка 335). Сейчас при мёртвой странице
скриншот и HTML молча не пишутся, но в лог уходит «Дамп сохранён», а фронт говорит
«проверьте скриншот» про пустую папку. Исправить:

- передавать в `_dump_failure` текст ошибки шага (поправить единственный вызов,
  ~строка 1306) и ВСЕГДА писать в папку `error.txt`: текст ошибки + имя шага + время +
  пометка «вкладка закрыта, скриншот недоступен», если page мёртв;
- «Дамп сохранён» логировать только если реально записан хотя бы один файл;
  возвращать путь, только когда папка непустая, иначе `None` (тогда фронт не покажет
  ссылку на пустую папку — поведение фронта уже завязано на наличие `debug_dir`).

## 9. Приёмка пользователем (ручная, ПОСЛЕ зелёных тестов; делает только пользователь)

1. `start-chrome.bat` → в Chrome залогинен на avito.ru.
2. `python backend/app.py` → `localhost:8000/#/draft` (сервер без авто-перезагрузки —
   после правок перезапустить).
3. Форма с `drafts_count=2..3` → запуск.
4. Ожидание: все шаги зелёные на каждом черновике, итог «Сохранено N из N», N черновиков
   в Авито (Мои объявления → Черновики). Если упадёт — в `debug/publish/{job_id}/` теперь
   будет `error.txt` (и скриншот, если вкладка жива), в `logs/publisher.log` — тики
   ожидания с URL; этого хватит для следующего раунда диагностики.
