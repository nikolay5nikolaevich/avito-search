# CLAUDE.md

## Проект
Локальный сервис автовыкладки объявлений на Авито. Пользователь заполняет форму,
сервис готовит N уникальных вариантов (текст + фото) и **публикует их на Авито**
через живой Chrome по CDP.

Второй, законченный сценарий — аналитика спроса: парсинг выдачи по городам,
средние просмотры/день, топ-3 объявления, CSV, кэш 24 ч.

Боевой прогон пройден (16.08.2026): 17 из 17 объявлений отправлены. Разбор всех
сбоев того прогона — `docs/reports/2026-08-16-publication-errors.md`,
это лучший источник по реальному поведению Авито.

## Публикация — деньги и необратимость
Публикация **реальная и платная**. Полный путь в `publisher.py`:
форма → «Продолжить» → экран стоимости просмотра (slider) →
«Продолжить с минимальной ценой» → `/pro/performance` → «Продолжить без услуг».

Правила этого участка (нарушение стоит денег):
- Неизвестная подпись кнопки, услуга или цена — **останавливаем сценарий**, не угадываем.
  Это защита, а не баг: см. проверки подписей и `_norm_label`.
- Финансовые клики **не повторяются** при ретраях. Ретраи — только для безопасных GET.
- Цена ставится через штатный slider и сверяется обратным чтением (`Decimal`).
  Нет нужного значения на шкале — стоп с показом соседних, не подмена молча.
- Отказ от услуг — только на `/pro/performance`, повторный клик запрещён.
- Возобновление с checkpoint **есть** — кнопка «Продолжить» в интерфейсе и
  `POST /api/publish/resume/{job_id}` (`publish_state.py`, `resume_plan`).
  Один пакет за раз: второй `/start`/`/resume` при активной задаче — 409,
  межпроцессный lock в `tmp/publish/publish.lock`. Незавершённую задачу
  закрывают явной кнопкой «Закрыть задачу» (`POST /api/publish/close/{job_id}`),
  новый `/start` старую задачу молча не закрывает — не путать перезапуск
  сервера (безопасен, состояние на диске) с ручным перезапуском ПАКЕТА с формы
  (создаёт дубли уже отправленного). `items_published: 0` не значит «на Авито
  ничего нет» — денежный клик мог уже пройти, смотри `step`/`resume_plan`,
  а не только счётчик.
- Статус «Отправлено» ≠ «Опубликовано»: проверка появления карточки удалена
  по требованию пользователя, судьба на модерации не отслеживается.

## Запуск
Авито банит любой Playwright-браузер, поэтому только через живой Chrome:
1. `start-chrome.bat` → Chrome с портом 9222, руками зайти на avito.ru.
2. `python backend/app.py` → `localhost:7777` (подключится по CDP).

Перед первым запуском: `cd frontend && npm install && npm run build`.
Env: `AVITO_CDP_URL` (для IPv4 — `http://127.0.0.1:9222`), `AVITO_MAX_ITEMS`.

Стек: Python 3.11+, FastAPI, Playwright, BeautifulSoup, SQLite; React + Vite
(`frontend/`, сборка в `frontend/dist/`, раздаётся бэкендом).

## Карта кода
- `app.py` — FastAPI: аналитика (`/api/search|status|results`, `/export.csv`),
  публикация (`/api/publish/start|status|result|categories`),
  подготовка вариантов (`/api/publish/prepare*`), раздача `frontend/dist/`.
- `publisher.py` — весь живой сценарий Авито: форма, автокомплиты, фото, цена, услуги.
- `preparation.py` — оркестрация «подготовить N вариантов»;
  `text_variation.py` / `photo_variation.py` — движки уникализации (без ИИ).
- `category_profiles.py` — профили категорий (пиджаки / кроссовки / кофты-футболки):
  `category_id`, params, размерные сетки, опциональный «вид товара».
- `avito_publish_selectors.py` — селекторы формы публикации.
  `avito_selectors.py` — селекторы **выдачи**. Не смешивать.
- `parser.py`, `cities.py`, `filters.py`, `analytics.py`, `cache.py` — аналитика спроса.
- `outreach.py` / `outreach_store.py` — рассылка продавцам в чат Авито и её история.
- `seller_scan.py` — разбор продавца: первые N объявлений профиля, просмотры всего/сегодня, CSV.
  Профиль — бесконечная лента без пагинации, Авито повторяет в ней часть объявлений (дедуп по ID).
  Витрина `/brands/<id>/all` показывает 12–15 штук — сбор сперва уходит по «Показать все».
- `agents_registry.py`, `journal.py`, `stats_collector.py`, `strategist.py` —
  реестр агентов, общий журнал событий, сбор статистики по API, гипотезы.
- `browser.py` — подключение к Chrome по CDP. `diag.py` — диагностика в `debug/`.
- `frontend/src/pages/` — `WorkspacePage` (аналитика), `DraftPage` (публикация),
  `OutreachPage` (рассылка), `SellerScanPage` (разбор продавца), `AgentsPage` (статистика и гипотезы).
- `tests/` — smoke (`publish_smoke_test.py`, `prepare_smoke_test.py`, `smoke_test.py`)
  и точечные проверки рискованных мест (`test_publish_financial_flow.py`, CDP, автокомплиты).

## Грабли
- Сервер **без auto-reload** — после правок перезапускать вручную. Симптом забытого
  перезапуска: фронт шлёт новый контракт, бэк отвечает по старому.
- Playwright держим на **1.60.0** — на 1.62 драйвер валит publish-smoke по EPIPE.
  Диагноз под вопросом: тот же EPIPE воспроизведён и на 1.60.0 при определённом
  тайминге выхода процесса (похоже на обычное поведение Node-драйвера, а не
  специфику версии) — перепроверить перед следующим обновлением Playwright.
- CDP виснет («ws connected → Timeout»), если есть зависшие вкладки Авито; лечение —
  закрыть их, оставив одну. Подключение к ws конкретной вкладки не помогает.
- Автокомплиты (бренд, адрес) фиксируют значение **только кликом по пункту** подсказки.
  Набранный текст не принимается; адрес ищем внутри контейнера гео, иначе улетит
  чужой город.
- Менял логику метрик аналитики → удали `cache.db` (ключ кэша сам не изменится).
- Не в git: `.venv/`, `cache.db`, `logs/`, `debug/`, `tmp/`, `trash/`, `.pw-profile/`,
  `frontend/dist/`, `node_modules/`, `docs/_internal/`.
  В `debug/` персональные данные — наружу не отдавать.
- `trash/` — карантин для удаляемого: кладу туда, пользователь удаляет сам.
- `AGENTS.md` в корне — копия этого файла для Codex. Правишь один — правь оба.
- VPN: Авито требует РУ-IP, Claude — не-РУ. Разводим по времени, артефакты через `debug/`.

## Стиль
PEP 8, type hints, комментарии и логи по-русски, `logging` вместо `print`.
Ошибка одного объявления/города/шага — лог и пропуск со статусом, не падение пакета.
Пользователю — готовые команды и файлы целиком, не диффы (он новичок: JS, немного
Python, Node не знает). Общение по-русски.
